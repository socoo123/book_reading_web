# 第 14 章｜做正确的事

**Doing the Right Thing · 正确运行之后，还要回答系统怎样影响人**

一个系统可以没有丢写、没有重复扣款，也能在毫秒内作出决定，却仍然使某些人更难获得工作、住房或保险。[第13章](ch13.md)讨论怎样组合数据系统并承担端到端正确性；最后一章把边界继续向外推：数据来自谁，决定影响谁，收益和错误的代价分别由谁承担？

本章的主线有两条：用数据预测并干预人的生活，怎样产生偏见与反馈；收集、保留和使用个人数据，怎样改变人与组织之间的权力关系。作者提出的伦理判断、历史事件和本笔记补出的工程解释，下面分别说明。

<a id="purpose-and-impact"></a>

## 01　伦理责任从系统目的延伸到实际后果

原书先提醒：数据集里看起来抽象的字段，往往对应人的身份、兴趣和处境。赚钱、提高效率或提供便利可以是系统目的，但目的良好并不保证后果良好。一个提高贷款筛选效率的工具，也可能把过去受到不公平待遇的人持续排除出去。

**作者的价值主张**是，工程师不能只负责程序是否按规格执行，而把对人的伤害视为规格制定者的问题。伦理又不像类型检查：公平、尊严和自主权在不同情境中需要解释，无法靠一张勾选完就永久有效的表来解决。它要求与受影响者对话，在实际使用中反思、修正，并对结果负责。ACM伦理准则是原书列出的职业参考，而不是替代判断的自动裁决器。

<a id="predictive-exclusion"></a>

## 02　每家机构的一次谨慎，可能累积成一个人的持续排斥

**预测分析（predictive analytics）**从已有数据推测尚未发生或尚未观察到的结果。原书区分预测天气、疾病传播，与预测某个人会不会违约、再犯或产生高额保险索赔。区别在于后者直接进入针对个人的机会分配，并不表示天气或公共卫生模型没有伦理问题；旧稿把前者写为“无争议”，范围过大。

银行希望少放坏账，公司希望少招不合适的员工。从单家机构看，错过一笔普通业务的代价可能小于接受一次高风险业务，于是“拿不准就拒绝”成为合理的局部策略。可是，被贴上风险标签的人若在招聘、租房、贷款和保险中反复遇到拒绝，损失就不再是一次交易，而是基本社会参与的空间。

原书借“算法监狱”描述这种累积排斥：标签无论准确与否，都可能扩散成大量难以申诉的否定。这个比喻不是说所有商业拒绝等同刑罚，而是要求我们看见成本不对称——机构省下的是个别风险，被拒者承担的可能是一整条生活路径被关闭。

<a id="bias-and-proxies"></a>

## 03　删掉敏感字段，并不能删掉历史偏见

人类决策会有偏见，算法也可能帮助发现并减少它；原书没有把二者排列成固定的优劣顺序。关键变化是，机器学习常让决策规则从历史样本中归纳出来。如果历史记录包含制度化的不公平，拟合这些记录就可能把不公平当作值得复制的规律。预测过去的结果，与判断未来应当怎样，是两项任务。

**代理变量（proxy variable）**是能间接传递另一特征信息的变量，不要求开发者有意绕过限制。原书以居住隔离为前提：邮编，甚至能反映居住区域的IP地址，可能与族群或社会经济处境高度相关。移除“族群”字段后，模型仍可能从地域等特征恢复类似的区分。

用一个**笔记假设**看这条路径：某地区过去难以获得稳定工作，历史样本中的财务困难较多；模型把地区当作风险信号；一位自身履约记录良好的居民因此被拒。输入字段都真实、程序也没有错误，却仍然可能把群体处境强加给个人。是否构成法律上的歧视还取决于地域、领域、依据和具体影响，不能由“相关”二字直接判定。

原书借“给偏见洗白”的讽刺提醒我们：数字形式不能自动赋予结论公正性。这里也不应沿用旧稿“机器学习参数人都读不懂”的绝对说法；不同模型的可解释程度不同，而能解释某字段的作用，也不等于已经证明使用它合理。要改善未来，还须公开讨论目标、代价和哪些历史模式不应延续。

<a id="accountability"></a>

## 04　概率不是判决，解释之后还要有人处理错误

原书把传统借贷记录与广泛画像作对照：前者至少较容易追问“这个人过去是否按时还款”，后者可能转向“与此人相似的人过去怎样”。这是输入与推理范围的比较，不是信用评分与机器学习互不重叠的技术分类。宽泛画像会增加错误归类的机会，也使当事人更难知道应当纠正哪份资料。

统计上的正确仍不足以裁决个体。**笔记假设**某个风险组有100人，模型给出的违约概率为20%，最后恰有20人违约；这支持该组的概率校准，却没有告诉我们是哪20人，更不能证明其余80人都应被拒。平均寿命也不意味着每个人都会在平均年龄去世。把概率转成拒绝阈值，是组织作出的政策选择，必须解释怎样分配误判成本。

**责任（responsibility）**关心谁作出和执行选择，**问责（accountability）**还要求其能够说明依据、接受质疑并处理后果。原书用自动驾驶事故、信用歧视和司法审查提出问题：人不能说“是算法决定的”，就让责任消失。

落实到前面的假设，申诉应能沿着“错误输入 → 负责修正的人 → 重新评估决定 → 处理已经造成的影响”往前走。只展示一张特征重要性图，或安排一个无权改判的人复读模型输出，都不足以完成这条路径。这是本笔记对原书问责要求的展开。数据也可以识别需要援助的人；同样的脆弱性画像若用于推销高息借款，则可能加重困境。评价必须包含用途和后果。

<a id="feedback-loops"></a>

## 05　预测参与改变世界，下一轮数据就不再独立

**反馈循环（feedback loop）**意味着系统输出改变了环境，环境又产生下一轮输入。原书最清楚的例子是雇主用信用分筛选求职者：一个原本可靠的员工遭遇无法控制的不幸，开始错过还款；信用下降使其更难找到工作；收入不足又使还款更困难，分数继续下降。起点是一次外部冲击，筛选制度却可能让冲击长期化。

下图顺时针读，最重要的是底部返回路径：后续记录不仅描述这个人，也包含此前决策造成的影响。

![外部不幸使还款困难、信用分下降；若雇主用信用分筛选，就业机会减少，收入更难恢复，再返回还款困难，形成自我强化的循环。](../diagrams/exports/ch14-credit-feedback.svg)

图 14-2：实线表示本例假定的影响方向，虚线标出被决策改变的处境返回后续记录。它不是“所有雇主都这样做”的现实比例图，也不把信用分当作工作能力的已证实替代指标。点击[查看大图](../diagrams/exports/ch14-credit-feedback.svg)。

如果模型又把后续困境当成“最初拒绝果然正确”的证据，就会混淆预测对象与干预结果。**系统思维（systems thinking）**因此要把人、机构规则、激励和长期变化一起纳入分析。可以追问信用筛选是否适用于当前职位、是否允许解释暂时困难、支持措施能否改变还款能力，而不是只提高分数拟合精度；这些是笔记提出的分析方向，不是原书已经验证的解法。

推荐系统也可能形成类似回路：展示较窄的观点，收集对此的点击，再据此继续缩窄内容。原书担忧回音室、错误信息和两极分化；这是风险机制，不能直接推出所有用户或所有选举的统一因果效果。

**原书案例的证据边界：**印刷589页把德国加油站算法定价写成“算法学会合谋”；旧稿又补出无人指示、试错后收敛的过程。对应研究的作者摘要报告：采用定价软件后，非垄断站点的利润率上升，双寡头市场中则在双方都采用时上升。这是市场竞争结果的实证证据，不能仅凭它确认算法内部如何学习。因此保留“算法互动可能削弱竞争”，不把自发学习合谋机制当作该研究直接观察到的事实。

<a id="tracking-and-surveillance"></a>

## 06　跟踪的关键变化，是它开始为谁服务

用户主动存一份文件，希望服务替自己保存；系统顺带记录浏览、位置和社交关系，并据此开展其他业务，双方的关系就变了。点击数据可以改善搜索排序，购买组合可以改善推荐，A/B测试可以帮助比较界面。作者承认这些收益，问题在于跟踪是否越过实现这些功能所需的范围。

广告模式可能鼓励服务不断延长参与时间、细化画像、扩大关联和保留期限。此时收集主要服务广告客户，用户利益未必与之重合。原书把“数据驱动”换成“监控驱动”作为带有批判性的思想实验，要求读者重新观察这种关系；并非所有采集都因此被定义成监控。

数字化改变了规模：位置、支付、通信和健康信息能够被自动汇集，传感器还能支持超出原始用途的推断。原书引用2015年手表运动传感器推断输入的研究，说明推断能力值得注意；这里按原书转述，不把实验结果推广成所有手表都能读取任意密码。“我没有什么要隐藏”也不能替他人作决定：同一条健康或位置记录，对处于不同生活环境的人可能有完全不同的后果。

**美国历史案例：**FTC于2025年1月16日指控GM与OnStar在未充分告知、取得明确同意的情况下收集、使用并出售精确位置和驾驶行为数据；其公告说明，相关消费者报告被保险公司用于拒保或定价。此处采用的是当时的监管指控与拟议和解公告，不冒称法院事实判决，也不把该案写成所有车企的共同做法。它展示了从“帮助驾驶”到影响保险机会的用途延伸。**后续状态补充：**FTC于2026年1月14日公布最终和解命令，包括五年内不得向消费者报告机构披露所涉位置与驾驶行为数据等要求；这是和解执法进展，不改写为法院就全部指控作出的事实判决。

<a id="consent-and-choice"></a>

## 07　一个“同意”按钮，不能独自证明选择自由

原书从三处质疑“用户自愿用数据换服务”。首先，必须区分提供功能所需的数据与商业模式想要的数据；某项跟踪能增加广告收入，并不自动说明没有它就无法实现用户请求的功能。

其次，同意要有可理解的对象。用户可能知道自己上传了照片，却不了解行为日志、外部来源和全体用户数据怎样组合成派生画像。一人的记录还可能暴露未注册亲友的信息。若组织只给出笼统条款，却不让人理解收集范围、用途、保留和接收者，就很难说对方作出了有意义的选择。

最后，要看拒绝成本。**网络效应**使服务的价值随着参与者增加而增强；当亲友或职业机会集中在某个平台，退出就可能带来社会成本。吸引人不断返回的产品设计，又增加退出难度。条款由一方制定，另一方只能全盘接受或放弃，这种关系与可协商的对等交换不同。不同人的时间、知识和替代资源也不同，不能因为自己可以退出，就认为人人都有相同选择。

**欧盟法条核对，2026-11-07：**GDPR第4(11)、7条及序言32、42、43要求同意自由、具体、知情、明确；预勾选、沉默不能代替积极表示，撤回应与给予同意一样容易。第6条还列出其他处理依据，因此“没有同意就一律违法”同样不对；合法利益也须满足必要性与权利衡量条件。这些规定为原章提供具体参照，不能把一次点击当作双方权力已经对等的证据。

<a id="privacy-as-agency"></a>

## 08　隐私包括决定用途，而不只是把内容藏起来

有人愿意公开生活，不表示其放弃了所有隐私。原书把隐私解释为一种**决定权**：在特定情境下，选择向谁披露什么、允许怎样使用。罕见病患者可能愿意让研究者分析病历以寻找疗法，却不愿同样的资料被拿来影响就业或保险。信息相同，关系和用途不同，选择就可以不同。

读下图时注意分支上的文字：同意某个研究用途，没有自动打开另一条使用路径。

![患者在知情选择下把病历交给研究者用于约定研究；从同一资料转向就业或保险判断的虚线标为另一个用途，不由研究同意自动涵盖。](../diagrams/exports/ch14-purpose-choice.svg)

图 14-3：实线表示原书例子中愿意分享的用途，虚线表示需另行判断的用途扩展。图示表达个人选择的伦理问题，不声称同意是医疗数据所有处理情境的唯一法律依据。点击[查看大图](../diagrams/exports/ch14-purpose-choice.svg)。

作者所谓“隐私权转移”，是对实际控制关系的批评，不是说法律权利已合法转让。公司决定怎样分组、推断和定向投放，个人却无法理解或改变这些决定；即使广告客户不能从目标群体里认出具体姓名，个人仍可能失去对敏感信息用途的控制。匿名与否不能独自回答全部问题。

数据正确也可能带来伤害。例如，回忆功能再次展示一段真实但痛苦的经历。原书要求预期错误、不合意和不适当的输出，并提供处理办法。让用户不再看到这类内容、纠正错误资料、理解处理用途，是不同层面的控制；“其他用户不可见”的开关并不自动限制服务内部分析。“不卖数据”也不能代替对内部用途的说明，实际边界仍取决于系统设计、适用规则和承诺。

<a id="assets-and-power"></a>

## 09　数据有价值，也把未来风险带进今天的架构

把行为数据称为“数据尾气”，容易让分析听起来像回收无价值的废料。原书引入另一种经济解释：如果行为数据支撑广告收入，用户产生这些数据的活动也可以被视为创造价值的劳动。这是分析商业关系的视角，不是已经确定的劳动法律身份。

数据经纪人购买、整合、分析和转售资料，展示了个人数据的商业价值。价值也使更多主体想取得它：收购者、债权处置中的买家、政府或攻击者。原书进一步要求考虑内部泄露、管理层更换以及未来政治环境的变化；今天善意的收集者，并不能保证多年后的控制者保持同样用途。

“有毒资产”“危险材料”与“新铀矿”是作者引用的风险比喻，不是数据没有收益的断言。核心推理是：保留一份数据，就同时保留未来使用与滥用它的可能。加密与访问控制能减少部分未经授权的访问，却不能单独限制获得授权后的有害决策。减少不必要的数据，直接缩小可被取得和滥用的范围。

权力不对称还在于可见性的方向：组织能够细看个人，而个人难以审视组织怎样分类、推断和决策。原书批评的不是某个存储产品，而是这份观察和干预能力缺少相应的可质疑、可纠正与公共监督机制。

<a id="industrial-revolution"></a>

## 10　工业革命的类比：把外部代价算回进步之中

原书以工业革命作历史类比：技术进步长期提高生产能力和生活水平，也伴随污染、危险劳动和童工等严重代价。环境保护、工作安全和食品卫生等制度逐步形成，增加了部分经营成本，却使收益不再以同样方式建立在他人的损害之上。这是作者的概括性历史论述，本笔记不补造各国立法时间线。

它与数据系统的连接点是**外部成本**：企业取得收集收益，泄露、排斥或自主权丧失的代价却可能落在别人身上。原书借Schneier的“信息时代污染”比喻强调，产生信息以后如何约束、保存与处置，都是系统生命周期的一部分，不能把磁盘还能装多少作为唯一尺度。

类比不意味着数据与工业废物具有相同物理性质，也不能直接推出应照搬某一套环保法规。它支持的是一个制度问题：当各组织都有“多收一点更有利”的激励，不能只指望受影响者各自防守；还需要共同限制。作者相信可以在保留信息技术收益的同时改善这些关系，这是价值选择与行动方向。

<a id="law-and-minimization"></a>

## 11　立法与自律，最终要进入采集、用途和保留决定

原书指出“先全部收集、永久保存、以后再探索用途”的倾向，与数据保护原则存在张力。三件事需要分开：**用途限制**决定为何处理，**数据最小化**决定为此需要哪些数据，**保留限制**决定可识别的资料需要保存多久。只设置一个很长的过期时间，不代表采集本身已经必要。

**原文边界修正：**印刷596页把探索未预见用途与GDPR要求写成直接对立，旧稿也沿用。欧盟GDPR第5(1)(b)限制的是不相容的进一步处理，第6(4)给出相容性评估因素；第5条及第89(1)对满足保障条件的研究、统计等另有安排。因此不能推出“所有新用途或探索分析一律禁止”，也不能反过来认为挂上“研究”标签就能任意使用。此处依官方条文作范围限定，不称为出版社已确认勘误。

作者也承认限制存在机会成本：共享医疗数据可能促进诊断与治疗，限制不当也可能阻碍有益研究。真正的取舍是明确收益、必要范围和保障条件，而不是把“创新”或“隐私”当作不必继续解释的答案。原书对执法薄弱、行业文化尚未明显改变的评价，属于其写作语境下的判断，不作为本笔记对2026年所有地区的独立统计结论。

作者给出的第一步很实际：从开始就少收，不再需要时尽快清除，同时让用户理解用途并保留控制。**笔记工程展开：**假设一项搜索改进只需要短期点击统计，应先说明需要哪些字段、什么粒度、谁能使用和何时结束；若准备转作个人画像，就重新审视用途与依据。删除也要沿派生路径检查：源记录删掉，但分析表、日志或重建流程重新生成同样资料，预期的退出就没有完成。[第12章的历史与删除](ch12.md#state-history)说明了不可变数据的这一张力；密钥销毁式删除仍依赖密钥及明文副本被妥善处理。

立法提供权利与限制，自律让团队在具体选择中承担责任。作者并没有给出一个解决全部伦理冲突的算法，而是要求停止把人只当作待优化的指标，让参与、解释、纠错和必要的数据处置成为实际工作。
