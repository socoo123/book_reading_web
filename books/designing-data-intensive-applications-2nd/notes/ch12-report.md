### 重要纠错与限定

下列内容已就地写进正文，文末来源区记录对象、原表述、依据和修正：

| 对象／原表述 | 问题与修正 | 依据 |
| --- | --- | --- |
| 原书499页／旧稿“至少22小时” | 20TB／250MB/s为80000秒、约22.2小时；仅理想容量预算，不能成为通用下界 | 原页、单位复算与保留条件 |
| 原书499页／旧稿“对象存储消息就是Iceberg表” | 对象存储介质不决定表格式；Kafka分层存储保存日志段和索引 | Kafka4.1 Tiered Storage |
| 原书506页／旧稿“Cassandra多数写入才可见” | 按读写一致性级别及实际副本状态判断，ONE不要求多数；逐节点CDC不是单一提交顺序 | Cassandra5.0 Dynamo文档 |
| 原书517页产品并列／旧稿统一IVM概括 | ClickHouse增量MV右侧表更新不触发既有结果更新，不等同两边任意变化均维护连接 | ClickHouse官方增量MV文档 |
| 旧稿outbox“不是双写” | 确有两次同库写，关键是共享本地事务；发布与消费者仍有重投边界 | 原书507—508页 |
| 旧稿将S−R加到事件时间 | 符号方向相反；正确为E+(R−S)，需小网络延迟与稳定时钟偏移假设 | 原书时间段、设备快两分钟复算 |
| 旧稿事件时间必然确定／watermark减5秒保证迟到更新 | 确定性还依赖历史维度与输入；水位生成、触发、允许迟到、清理和下游更正分别约定 | Flink2.1时间文档、原书518—526页 |
| 旧稿sink见屏障即检查点完成／可撤销所有输出 | 必须收齐所需持久化确认并可靠记录完成；外部效果需要事务sink或接收方原子去重 | Flink2.1容错文档、Kafka4.1事务语义 |
| 跳跃窗例子／乘积求导类比 | 指定步长与对齐后才有不能共同落窗结论；有限批量变化有交叉项，顺序维护可吸收该项 | 原书522、525页与教学模型；不称原公式错误 |

补充修正还包括：保序不是只能每消费者独立队列；日志经典消费者组不能涵盖所有share groups语义；位点统一为下一条；事件时间不是所有统计的唯一正确选择；历史维度的保留粒度取决于版本键；同事务ID去重与隔离令牌处理不同风险。
